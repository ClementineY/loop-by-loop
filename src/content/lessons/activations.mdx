## Which activation should sit between layers?

The previous lesson established why a bend is necessary. Now compare what each activation sends forward and what its local slope sends backward. Change both the function and `x`; the formula, curve, tangent, output, and six-layer gradient multiplier update together.

<ActivationExplorer client:visible />

Backpropagation multiplies the incoming gradient by the local slope:

- **ReLU** is fast and keeps a slope of 1 for positive inputs, but blocks gradients for negative inputs.
- **Sigmoid** maps to `(0, 1)`, useful for a binary probability output, but saturates at both ends.
- **Tanh** maps to `(-1, 1)` and is centered on zero, but also saturates.
- **Leaky ReLU** preserves a small negative slope, reducing completely inactive units.

## Build a block

```python
import torch.nn as nn

block = nn.Sequential(
    nn.Linear(8, 32),
    nn.ReLU(),
    nn.Linear(32, 2),
)
```

The final layer has no activation because `CrossEntropyLoss` expects raw scores called logits. It applies the numerically stable probability conversion internally.

## Saturation and dead units

At sigmoid input `x=6`, the curve is almost flat. Multiplying by that tiny derivative shrinks the gradient reaching earlier layers. ReLU avoids positive-side saturation, although a unit receiving only negative inputs has zero gradient and can become “dead.” Initialization, normalization, and sensible learning rates help keep activations in useful regions.
