## Does PyTorch modify one permanent graph?

No. Eager PyTorch is **define-by-run**: Python runs, and autograd records the tensor operations that produced this result.

Run the function again and PyTorch records a new route. A different `if` branch can therefore produce a different graph.

## Three moments

**Forward records.** Results point back to the operations that created them.

**Backward follows.** `loss.backward()` walks that route and fills leaf gradients.

**The next call starts fresh.** The old route is normally released after backward.

```python
w = torch.tensor(-1., requires_grad=True)
loss = (2 * w + .5) ** 2   # record this run
loss.backward()            # follow it backward
```

<Callout type="note" title="In-place is not the defining feature">
In-place operations are constrained because backward may need an earlier tensor value. PyTorch checks mutations rather than treating them as its graph-building strategy.
</Callout>
