## A graph made by ordinary code

PyTorch uses a dynamic graph: running tensor operations creates nodes and edges as Python executes. An edge means “this result depends on that value.” The graph can change on every example, which is why regular loops and conditionals work naturally.

<AutogradGraph client:visible />

The gradient at an addition does **branch**, but it does not get divided between the inputs. For `s = m + b`, both local derivatives are 1: moving either `m` or `b` by one unit moves `s` by one unit. Each parent therefore receives the full upstream gradient. If several downstream paths later meet at the same value, those separate gradient contributions are added together.

During the forward pass, operations save just enough context for their backward rule. Multiplication saves its inputs. Tanh saves information needed for `1 - tanh(x)²`. These saved values consume memory, so inference should not build a graph.

```python
model.eval()
with torch.no_grad():
    predictions = model(validation_images)
```

`torch.no_grad()` temporarily prevents graph recording. It is the normal choice for validation and inference.

## Detach one value

Sometimes most of a calculation should remain differentiable but one value should be treated as a constant:

```python
teacher_target = teacher(images).detach()
student_output = student(images)
loss = torch.nn.functional.mse_loss(student_output, teacher_target)
```

The student's path remains in the graph. The teacher output shares its data but no longer carries a gradient path back to the teacher.

## Leaves and intermediate values

Parameters are leaf tensors: they were created directly and require gradients. PyTorch retains `.grad` for leaves by default. Intermediate results participate in backpropagation but normally discard their gradients afterward to save memory.
