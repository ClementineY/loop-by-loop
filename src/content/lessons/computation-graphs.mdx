## Sometimes a value is data, not a learning route

Imagine a student model learning to match a teacher model. Both produce ordinary tensor values, but only the student should be updated by this loss. Toggle the teacher target between connected and detached, then run backward.

<DetachLab client:visible />

## Detach keeps the value and drops its history

```python
teacher_prediction = teacher(images)
target = teacher_prediction.detach()

student_prediction = student(images)
loss = loss_fn(student_prediction, target)
loss.backward()
```

`target` contains the same numbers as `teacher_prediction`. The difference is its role in autograd: it has no route back through the teacher. The student branch remains connected, so student parameters still receive gradients.

This is useful for fixed targets, logged values, plots, metrics, and any branch that should inform a calculation without being trained by it.

## Detach one value; disable recording for a block

| Control | Mental model | Typical use |
| --- | --- | --- |
| `value.detach()` | Cut the history behind this value | Teacher targets, metrics, stored features |
| `with torch.no_grad():` | Do not record anything inside this block | Validation and inference |
| `requires_grad_(False)` | Freeze this leaf parameter | Frozen model layers |

```python
model.eval()
with torch.no_grad():
    validation_predictions = model(validation_images)
```

<Callout type="info" title="A useful test">
Ask: “Should this loss be allowed to update what produced this tensor?” If the answer is no for one already-computed value, detach it. If no gradients are needed anywhere in a whole block, use `torch.no_grad()`.
</Callout>

## What receives `.grad`?

User-created parameters are leaves. Their `.grad` fields are retained after backward because optimizers need them. Intermediate tensors still carry gradients through the graph, but PyTorch normally does not keep their `.grad` fields once backward is finished.
