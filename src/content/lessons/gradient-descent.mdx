## Why not take the biggest downhill step possible?

Gradient descent repeats one small operation:

```text
parameter ← parameter − learning_rate × gradient
```

The gradient points uphill, so subtracting it points downhill. The learning rate decides how far to travel. It is not merely a speed control: a rate that is too large can jump across the valley and grow without bound.

<GradientDescent client:visible />

Try learning rates `0.03`, `0.2`, `0.8`, `1.0`, and `1.05`. On this quadratic, values below 1 converge, exactly 1 flips sides forever, and values above 1 diverge. Real loss surfaces have different curvature in different directions, so there is no universal safe value.

## What does PyTorch update?

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.05,
    momentum=0.0,
)

optimizer.zero_grad()
loss.backward()
optimizer.step()
```

`step()` reads each parameter's `.grad` and applies the optimizer's update rule under `no_grad`. It does not recompute the loss. The next forward pass reveals whether the new parameters helped.

## Why does the safe rate depend on the surface?

For `loss = p²`, one update is `p ← (1 − 2η)p`. Convergence requires the multiplier's magnitude to be below one, so `0 < η < 1`. A different curvature changes that interval. Real networks contain many curvatures at once, which is why a rate stable in one direction can oscillate in another.
