## Reproducible does not mean identical everywhere

Random initialization, data shuffling, augmentation, and parallel kernels can all change results. Seeds control random streams, but hardware and library implementations may still differ.

```python
import random
import numpy as np
import torch

seed = 42
random.seed(seed)
np.random.seed(seed)
torch.manual_seed(seed)

if torch.cuda.is_available():
    torch.cuda.manual_seed_all(seed)
```

For strict debugging, PyTorch can request deterministic algorithms, sometimes at a performance cost:

```python
torch.use_deterministic_algorithms(True)
```

## Record the experiment, not only the score

At minimum, preserve:

- Code revision and environment versions
- Random seed and data-split identity
- Model configuration and parameter count
- Optimizer, learning-rate schedule, batch size, and epoch count
- Training and validation curves
- Best checkpoint and the metric used to select it

A result without its conditions is an anecdote.

## Change one hypothesis at a time

Large sweeps are useful later. Early in a project, controlled comparisons teach more. State the hypothesis—“weight decay will reduce the validation gap”—then change only that factor and compare multiple seeds when the conclusion matters.
