## What is the portable unit?

`state_dict()` maps stable parameter and buffer names to tensors. Save it rather than serializing the entire Python model object, which couples the file to code paths and implementation details.

```python
torch.save(model.state_dict(), "model.pt")

restored = SmallCNN(classes=10)
restored.load_state_dict(
    torch.load("model.pt", map_location="cpu", weights_only=True)
)
restored.eval()
```

The architecture must be constructed before loading because the state dictionary contains values, not the `forward` method.

## What extra state does training need?

```python
torch.save({
    "epoch": epoch,
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),
    "best_val_loss": best_val_loss,
    "config": config,
}, "checkpoint.pt")
```

Optimizer state matters for momentum and Adam's running statistics. Without it, the parameters resume but the optimization trajectory does not.

<Callout type="warn" title="Treat model files as data from a trust boundary">
Load only expected formats from trusted sources. Prefer `weights_only=True` when reading PyTorch weight files and validate the model architecture and metadata separately.
</Callout>

## How do you prove the round trip worked?

After saving and loading, run a fixed input through both models and compare outputs. This small test catches missing buffers, configuration drift, or accidentally loading the wrong checkpoint.
